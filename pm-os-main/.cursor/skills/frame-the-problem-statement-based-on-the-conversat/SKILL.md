# Frame the problem statement based on the conversation transcript


## Required Inputs

Before proceeding, ensure you have:
- **session context**: Request this from the user if not provided


## Instructions

You are an expert in problem framing and user-centered design. Your task is to create a comprehensive Problem Framing Canvas based on the provided session context. This canvas will help stakeholders understand the core problem from a user's perspective.

First, carefully review the session context provided:

<session_context>
{{SESSION_CONTEXT}}
</session_context>

Now, follow these steps to create the Problem Framing Canvas:

1. Analyze the session context
2. Fill out the Problem Framing Narrative
3. Enumerate Context & Constraints
4. Create a Final Problem Statement
5. Review and critique your work

For each step, use <analysis> tags inside your thinking block to show your thought process and analysis. This will help ensure a thorough and accurate canvas. It's OK for this section to be quite long.

Step 1: Analyze the session context
<analysis>
- Identify the key persona experiencing the problem
- List their main pain points and underserved needs
- Determine their desired outcomes
- Identify barriers preventing them from achieving these outcomes
- Consider the root cause of the problem
- Note any emotional impacts on the persona
- Look for contextual and constraining factors
- Quote relevant parts of the session context to support your analysis
</analysis>

Step 2: Fill out the Problem Framing Narrative
Use the following template, ensuring each section is filled out from the persona's point-of-view:

Problem Framing Narrative:

I am:
- [Key characteristic 1]
- [Key characteristic 2]
- [Key characteristic 3]

Trying to:
- [Desired outcomes in a single sentence]

But:
- [Barrier 1]
- [Barrier 2]
- [Barrier 3]

Because:
- [Root cause of the problem]

Which makes me feel:
- [Emotional impact]

<analysis>
- Brainstorm multiple options for each section of the narrative
- Select the best options for each section
- Ensure each point is concise and relevant
- Check that the narrative flows logically
- Verify that the persona's perspective is maintained throughout
</analysis>

Step 3: Enumerate Context & Constraints
List the relevant contextual factors and constraints facing the persona(s), which may include:
- Geographic factors
- Technological limitations
- Time-based constraints
- Demographic considerations
- Any other relevant factors

<analysis>
- Consider how each factor specifically impacts the problem
- Ensure the list is comprehensive yet focused
- Check that each point adds value to understanding the situation
</analysis>

Step 4: Create a Final Problem Statement
Write a single, concise statement that provides a powerful and empathetic summary of the problem. This statement should be suitable for sharing with stakeholders, customers, engineering teams, and UX designers.

<analysis>
- Write three versions of the problem statement
- Distill the key elements from the narrative and context
- Ensure each statement is empathetic and user-centered
- Check that each captures the essence of the problem succinctly
- Verify that each provides a clear direction for potential solutions
- Choose the best version and explain why
</analysis>

Step 5: Review and critique your work
<analysis>
- Rate each section binary pass/fail for accuracy and completeness
- Does the canvas accurately reflect the information in the session context?
- Is each section filled out completely and appropriately?
- Does the narrative maintain the persona's perspective throughout?
- Are the context and constraints relevant and comprehensive?
- Does the final problem statement effectively summarize the situation?
- What improvements could be made to make the canvas more insightful or impactful?
</analysis>

Based on your review, make any necessary revisions to improve the quality and accuracy of the Problem Framing Canvas.

## Quote Selection Rules

- Start where the thought begins, and continue until fully expressed
- Include reasoning, not just conclusions
- Keep hedges and qualifiers — they signal uncertainty
- Include emotional language when present
- Cite with participant ID and approximate timestamp [P02 ~14:30]
- Do not combine statements from different parts of the interview
- If a quote would exceed 3 sentences, break it into separate quotes
